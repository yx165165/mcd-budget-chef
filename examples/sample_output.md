## 五、数据缺失时的行为（诚信设计）

仓库内 `白松露风味法式火腿安格斯厚牛堡` 刻意未收录营养数据，用于验证"不编造"机制：

```python
from nutrition import NutritionTable, summarize, format_totals
t = NutritionTable.load()
rep = summarize(['白松露风味法式火腿安格斯厚牛堡', '中薯条'], t)
print(format_totals(rep.totals))   # 热量 340kcal | 蛋白质 4.0g | ...
print(rep.missing)                  # ['白松露风味法式火腿安格斯厚牛堡']
```

输出：

```
热量 340kcal | 蛋白质 4.0g | 脂肪 16.0g | 碳水化合物 44.0g | 钠 270mg
⚠️ 以下餐品无营养数据（计为「无」，未计入总和）：白松露风味法式火腿安格斯厚牛堡
```

**缺失项被明确标注并从总和中剔除，不会用 0 或估计值蒙混。**
（对比：若按错误的实现，`中薯条` 的数值会被其它同名冲突项污染。）

## 六、名称归一化的单元验证

修复"键冲突"缺陷后，同名不同份量的餐品已可正确区分：

```
麦乐鸡(5块)  -> 250.0 kcal  ￥11.00
麦乐鸡(10块) -> 500.0 kcal  ￥20.00
```

（缺陷说明见 `workbuddy.md`：原实现把括号**连同内容**一起删除，
导致「麦乐鸡(5块)」与「麦乐鸡(10块)」归一化成同一个键，前者被后者覆盖，
营养数值因此虚高 250 kcal。）
